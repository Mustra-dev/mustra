Audit log

Every significant action in one chronological record — deployments, shell commands, compliance runs, policy and group changes. Each module keeps its own detailed history too; this is the spine that crosses them, which is what you need when reconstructing what happened rather than what one module did. Readable by anyone signed in, deliberately: a record only administrators can see is a weaker control than one everybody knows is kept.

Log level

Takes effect immediately across the whole server — no restart, which matters because restarting to turn on debug destroys whatever state you were trying to observe. debug is verbose; leave it on only while diagnosing something.

Forward to syslog, Splunk, or a SIEM

A live tap on the audit stream — every event as it happens. Different from a Connect export, which is a scheduled batch: an alert that arrives an hour later in a CSV isn't an alert. Point it at a Loki receiver (udp://host:514), a Splunk HEC-adjacent syslog input, or any SIEM that accepts RFC 5424 or CEF.

The target is dialled when you save, so an unreachable collector is reported here rather than silently never delivering.
