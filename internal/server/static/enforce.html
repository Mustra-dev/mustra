Policies

Comply tells you the firewall is off. Enforce turns it back on — on a timer, with nobody watching — which makes it the sharpest tool here, so three things are deliberate. A policy starts in report mode and stays there until you switch it, so you can see what it would do first. The endpoint re-checks after fixing, because a command exiting zero is not evidence the setting took. And a fix that fails 3 times in a row on one endpoint stops being sent there — otherwise a broken command runs every 30 minutes on every affected machine, forever.

New policy

A setting says what must be true, using the same rule dialect Comply uses — so c:systemctl is-active ufw -> r:^active means what it looks like. The remediation is what runs when it isn't true, per platform. Leave a platform blank and that setting simply reports drift there rather than pretending it was fixed.
