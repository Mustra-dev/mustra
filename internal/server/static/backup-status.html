Virtual machines and containers

Read from each Proxmox VE node by its Mustra agent (the Backups sensor): every guest's newest backup on any backup storage — Proxmox Backup Server, a directory, NFS — and whether an enabled backup job includes it. A guest is joined to the Mustra endpoint running inside it by its network card, then by name. A covered guest whose newest backup is older than the threshold is overdue and raises a notification once, and again when it recovers. Not covered means no backup job includes it, whatever old backups exist.

Backup systems

Read from the backup systems themselves, every 15 minutes: what each protects and when it last backed it up, verification, and how full its storage is. They add what no Proxmox job made — a host backed up with the Proxmox Backup Server client, a server Rubrik protects — and the same overdue notification applies to it. A Proxmox guest already listed above is marked, and alerts from its row there only.

Connect a backup system

Proxmox Backup Server: an API token with the DatastoreAudit role on /datastore (for the token and its user), e.g. proxmox-backup-manager user generate-token mustra@pbs status, and the server's certificate fingerprint (Dashboard → Show Fingerprint) unless it has a certificate this server trusts. Rubrik Security Cloud: a service account with a read-only role; its client ID and secret, and https://<account>.my.rubrik.com. Read only; tested against a stand-in, not yet a live account. An address inside your network must be on the internal destinations allowlist (Settings).
