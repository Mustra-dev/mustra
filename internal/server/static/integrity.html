Changes

Endpoints hash a watched set — authentication, authorization, scheduled execution, service definitions — and the server diffs consecutive snapshots. Detection happens here rather than on the endpoint on purpose: an attacker who can rewrite /etc/sudoers can also rewrite a baseline sitting beside it, so the comparison is made somewhere they cannot reach. Change that mustra itself caused during a deployment is labelled rather than hidden — without that, every patch run buries the findings that matter.

Watchlists

A named set of paths — files or directories — and, on Windows, registry keys, in addition to the built-in set every endpoint watches (authentication, scheduled execution, service definitions). A watchlist does nothing on its own; a monitor applies it to computer groups. The agent skips a path its OS does not have, so one watchlist can carry Linux, macOS and Windows paths together. Templates are a starting point aligned to a standard, not a certification.

Monitors

A monitor is a watchlist applied to computer groups. The union of an endpoint's monitors is its watch set, pushed to the agent and re-applied every five minutes, so an endpoint that joins a group or restarts converges. An agent older than 0.49.0 does not take a watch set and shows as needing an upgrade.

Labels

Rules evaluated as a change or event is recorded. Every matching label tags it; a label marked expected classifies it as change that needs no investigation — a package repository refresh, a config-management run at 02:00, anything during an open maintenance window. Change mustra itself caused during a deployment is already expected. What a rule cannot see is who made the change: no agent reports the process or user behind a file write yet, so those criteria never match.

Live events

The same watched set, reported as it changes rather than at the next sweep. The hash baseline and this run together and answer different questions: the baseline cannot miss a change made while the agent was down, and this one does not wait fifteen minutes to notice one made now. An event also triggers an immediate re-hash, so the diff above lands seconds after the write instead of at the next interval — and an indicator matching a path raises its finding while the file is still there.

What this does not say is who did it. An event carries the path, the operation and the time. Naming the process that wrote the file needs kernel plumbing mustra does not have, and a plausible guess would be worse than the honest gap.
